# Smooli

Прототип приложения для совместного прослушивания музыки. Полноценный локальный проект: React + Vite (клиент) и Node.js + Express + Socket.IO (сервер, реальная синхронизация без поллинга — события пушатся мгновенно всем в руме).

## Запуск в VS Code

1. Открой папку `smooli-app` в VS Code.
2. В терминале:
   ```
   npm install
   npm run dev
   ```
   Это одновременно поднимет сервер (`http://localhost:4000`) и клиент (`http://localhost:5173`).
3. Открой `http://localhost:5173` в двух разных вкладках/браузерах (или на телефоне и компьютере в одной Wi-Fi сети через `http://<твой-IP>:5173`) — так можно проверить синхронное прослушивание вдвоём.

Если хочешь запускать раздельно:
```
npm run server   # только backend, порт 4000
npm run client   # только frontend, порт 5173
```

## Структура проекта

```
smooli-app/
├── index.html
├── vite.config.js         # проксирует /api и /socket.io на сервер
├── src/
│   ├── main.jsx
│   ├── App.jsx             # всё приложение: экраны, компоненты, логика
│   └── storage.js          # обёртка над REST-хранилищем сервера
└── server/
    ├── index.js             # Express + Socket.IO, real-time sync румы
    └── db.json              # простое файловое хранилище (JSON)
```

## Что уже работает по-настоящему

- Регистрация/вход, никнейм 4–16 латинских символов, пароль до 32 символов
- Треки, альбомы, редактирование трека (обрезка/фейды), обложки
- Румы: создание, приглашения только от друзей, живой микс
- Синхронное прослушивание — мгновенно через WebSocket (Socket.IO), не через опрос
- Друзья, приглашения (приходят живьём, если получатель онлайн)
- Настройки: язык, тема, форма предложений — всё сохраняется на сервере в `server/db.json`

## Известные ограничения прототипа

- Аудиофайлы сохраняются как base64 в JSON-файле — нормально для тестов с короткими треками, но не годится для продакшена с большими библиотеками mp3. Для реального приложения треки нужно хранить как файлы на диске/в облаке (S3, etc.) и отдавать по ссылке, а не base64.
- `server/db.json` — не настоящая база данных, а простой файл. Для продакшена нужен Postgres/SQLite/Mongo.
- Нет HTTPS, нет реальной защиты от спама/ботов, нет rate limiting — всё это нужно добавить перед публикацией.

## Как превратить это в приложение для iPhone и Android

Проще всего — **Capacitor** (от команды Ionic), он оборачивает существующий веб-фронтенд в нативный контейнер:

```
npm install @capacitor/core @capacitor/cli
npx cap init Smooli com.yourname.smooli
npm run build          # соберёт клиент в папку dist/
npx cap add ios
npx cap add android
npx cap open ios       # откроет Xcode
npx cap open android   # откроет Android Studio
```

Важно: в мобильной сборке `http://localhost:4000` работать не будет — сервер нужно задеплоить на реальный хостинг (Render, Railway, Fly.io, VPS и т.д.) и в `vite.config.js` / `src/storage.js` указать его настоящий адрес вместо `localhost`. Также для реальных пользователей `server/db.json` нужно заменить на настоящую базу данных, иначе данные не переживут перезапуск/масштабирование сервера.

Альтернатива Capacitor — React Native (полностью нативный UI, больше переписывания, но лучше производительность и доступ к нативным API).
